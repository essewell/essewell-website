The site's purpose is to demonstrate engineering work, particularly work spanning physical systems, embedded computing, autonomous systems, software architecture, infrastructure and production software. ## Engineering Quality Use: 
- strict typing where applicable - semantic HTML - accessible interactions - responsive design - reduced-motion support - optimized images - static rendering where appropriate - structured project content Prefer simple architecture. Do not add dependencies without a concrete need. 
## Required Validation
 Before declaring work complete: 1. Intent Validation 2. Edge Case Audit 3. Integration Verification 4. UX Stress Test 5. Documentation Sync 
## Visual Validation 
Code correctness is not visual correctness. After every major UI implementation: 1. run the application 2. inspect the rendered result 3. inspect desktop 4. inspect mobile 5. assess visual hierarchy 6. assess spacing 7. assess typography 8. assess alignment 9. assess content density 10. correct weak design Do not accept mediocre UI merely because the application compiles. 
## Browser QA 
Where browser developer tooling is available, inspect: - console - runtime errors - network failures - responsive behavior - accessibility - layout - image loading - performance issues 
## Completion
 Do not stop at a scaffold or partially implemented landing page. A task is complete only when the requested surface is polished, functional and validated.
